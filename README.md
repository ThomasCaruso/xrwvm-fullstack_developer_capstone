# Best Cars — Full Stack Application Development Capstone

A full-stack dealership review platform built for the IBM Full Stack Application Development Capstone Project. Visitors can browse dealerships by state and read reviews. Registered users can sign in, publish purchase reviews, and see sentiment analysis attached to customer feedback.

## Architecture

```text
Browser
  ├── Static HTML/CSS pages: Home, About, Contact
  └── React pages: Login, Register, Dealerships, Dealer Details, Post Review
          │
          ▼
Django application
  ├── Authentication and sessions
  ├── CarMake and CarModel relational models (SQLite)
  └── Proxy endpoints
          │
          ├── Express API ── MongoDB
          │      ├── dealerships
          │      └── reviews
          │
          └── Sentiment Analyzer on IBM Code Engine
```

### Technology stack

- **Frontend:** HTML5, CSS3, JavaScript, React 18, React Router
- **Application backend:** Python, Django, Gunicorn
- **Data microservice:** Node.js, Express, Mongoose, MongoDB
- **Sentiment microservice:** IBM Code Engine endpoint supplied in the course lab
- **Delivery:** Docker, Kubernetes, GitHub Actions

## Implemented features

- Responsive Home, About, and Contact pages
- Registration, login, session-aware navigation, and logout
- Django `CarMake` and `CarModel` models with admin support and seed data
- Express/Mongo endpoints for dealerships and reviews
- Dealership list with state filtering
- Dealer detail and customer review pages
- Review sentiment indicators
- Authenticated review submission
- Multi-stage production Docker image
- Kubernetes Deployment and Service manifests
- CI checks for Python, Django, Express, and React

## Run locally

### 1. Start MongoDB and the Express API

```bash
cd server/database
docker compose up --build -d
curl http://localhost:3030/fetchDealers
```

The Express API is available at `http://localhost:3030`.

### 2. Configure Django

```bash
cd ../
cp .env.example .env
```

Edit `.env` and set `sentiment_analyzer_url` to the Code Engine URL generated by the course lab. Keep the local Express URL as:

```text
backend_url=http://localhost:3030
```

### 3. Build the React frontend

```bash
cd frontend
npm ci
npm run build
cd ..
```

### 4. Install and run Django

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py runserver 0.0.0.0:8000
```

Open `http://localhost:8000`.

## API routes

### Express/Mongo microservice

| Method | Route | Purpose |
|---|---|---|
| GET | `/fetchDealers` | Return every dealership |
| GET | `/fetchDealers/:state` | Return dealerships in a state |
| GET | `/fetchDealer/:id` | Return one dealership |
| GET | `/fetchReviews` | Return every review |
| GET | `/fetchReviews/dealer/:id` | Return reviews for one dealership |
| POST | `/insert_review` | Create a dealership review |

### Django application

| Method | Route | Purpose |
|---|---|---|
| POST | `/djangoapp/register` | Create and authenticate a user |
| POST | `/djangoapp/login` | Authenticate a user |
| GET | `/djangoapp/logout` | End the user session |
| GET | `/djangoapp/get_cars` | Return seeded car makes and models |
| GET | `/djangoapp/get_dealers` | Proxy all dealerships |
| GET | `/djangoapp/get_dealers/:state` | Proxy dealerships by state |
| GET | `/djangoapp/dealer/:id` | Proxy dealership details |
| GET | `/djangoapp/reviews/dealer/:id` | Return reviews with sentiment |
| POST | `/djangoapp/add_review` | Submit a review for the signed-in user |

## Build the production image

From the repository root:

```bash
cd server
docker build -t dealership:latest .
```

Run it locally while the Express API is available:

```bash
docker run --rm -p 8000:8000 \
  -e DJANGO_ALLOWED_HOSTS='*' \
  -e backend_url='http://host.docker.internal:3030' \
  -e sentiment_analyzer_url='REPLACE_WITH_CODE_ENGINE_URL/' \
  dealership:latest
```

## Deploy to IBM Container Registry and Kubernetes

The manifest intentionally contains placeholders. Replace them with the values generated by the Skills Network lab.

```bash
cd server

# Build and push
ibmcloud cr login
docker build -t us.icr.io/${SN_ICR_NAMESPACE}/dealership:latest .
docker push us.icr.io/${SN_ICR_NAMESPACE}/dealership:latest

# Prepare a lab-specific manifest without committing credentials or transient URLs
sed \
  -e "s|REPLACE_WITH_NAMESPACE|${SN_ICR_NAMESPACE}|g" \
  -e "s|http://REPLACE_WITH_EXPRESS_HOST:3030|${BACKEND_URL}|g" \
  -e "s|https://REPLACE_WITH_SENTIMENT_APP_URL/|${SENTIMENT_ANALYZER_URL}|g" \
  deployment.yaml > deployment.lab.yaml

kubectl apply -f deployment.lab.yaml
kubectl apply -f service.yaml
kubectl rollout status deployment/dealership
kubectl get pods
kubectl get services
```

For a lab environment that exposes applications through a proxy, use the URL supplied by the Kubernetes/OpenShift lab after the service is created.
